# 用户反馈与测试简介

---

在本教程中，您将探索：

- 用户反馈的目的。

- 如何将用户测试融入您的设计和开发过程中。

- 进行反馈会话和从目标用户那里获取可行反馈的技巧。

---

## 1. 概述

当您创建一个实时 3D 体验（或任何其他体验、产品或服务）时，它应该基于对目标用户的研究，满足明确的用户需求。

&nbsp;

用户测试和反馈是对您的项目进行“现实检验”的机会——与您在前期制作阶段创建的用户角色进行比较，理想情况下，邀请真实的人在整个开发周期内审查您的设计、原型和实时 3D 体验。

&nbsp;

## 2. 什么是用户测试和反馈？

**用户测试**的目的是收集定性和定量信息，以了解您的设计及其当前实施如何满足该体验所旨在解决的用户需求。换句话说，就是将产品作为一种体验进行测试。

&nbsp;

用户测试的输出是可行的反馈，您可以评估并用来改善您正在创建的体验。

&nbsp;

用户测试并不是一次性的活动。用户测试必须贯穿于生产的各个阶段。这样可以确保最终产品的高质量，满足目标受众的需求。参与用户反馈过程还将帮助您提升在界定范围、设计和实施解决方案方面的技能，以满足特定的用户需求。

&nbsp;

## 3. 为什么要进行结构化用户测试？

虽然从非正式反馈中可以获取有价值的信息，但用户测试不仅仅是将您的产品展示给某人并询问他们的看法。这是一个结构化的过程，旨在尽可能从测试者那里获取具体且有用的信息。协调的用户测试方法还将使您能够从不同用户那里收集数据，以便比较他们的反应，从而获得更好的数据集来支持评估和改进决策。

&nbsp;

理想情况下，您应该在项目设计和开发的不同阶段进行多次用户测试，无论您是在进行专业项目还是独自项目以帮助您学习。

&nbsp;

您可能会想，“还没准备好——等我完成后再展示给别人，获取他们的反馈！”这种感觉很自然，但当您的项目达到成熟状态时，您可能无法进行反馈所提出的重大更改。相反，尽早并频繁地进行测试！您测试和完善的次数越多，最终产品就会越好。

&nbsp;

## 4. 用户测试的阶段

用户测试过程通常遵循以下高层结构：

- 确定目标。

- 计划会话。

- 组织会话。

- 评估结果。

&nbsp;

## 5. 用户测试的计划

### 确定目标

在准备问题以获取用户反馈之前，您应确定：

- 您希望了解有关项目的哪些信息。

- 您将向用户展示什么以引导反馈（例如，线框图、设计模型或原型）。

&nbsp;

然后，您可以根据这些目标评估您的问题和测试会话计划，以确保它们能帮助您获取关于项目所需的信息。

&nbsp;

### 准备问题

接下来，您需要准备引导用户反馈的问题。根据您想要的反馈类型，您可以提出开放式问题、封闭式问题或两者的结合。

&nbsp;

**开放式问题**让用户自由解释他们的答案。示例包括：

- 您认为设计/原型/产品在多大程度上满足了 [用户需求]？

- 测试中有哪些时刻让您感到困惑，为什么？

- 您会如何改进这一体验？

&nbsp;

尽管这些问题在调查或问卷中可以使用，通过对话提问可能更有用。这允许您提出后续问题，深入了解测试者的想法。

&nbsp;

**封闭式问题**有预定的答案，类似于调查中常见的问题。这可能包括：

- 一系列陈述，用户需要为其评分，例如在 1 到 5 的范围内评定信心。

- 具有简单是/否回答的问题。

&nbsp;

这些问题在调查或问卷格式中表现良好；您不需要亲自询问它们。

&nbsp;

使用这两种类型的问题是有帮助的，不仅可以获得多样的信息，而且一些测试者可能会发现通过调查提供诚实的批评反馈比直接与人交流更容易。

&nbsp;

### 计划测试会话

当您定义了测试问题后，需要考虑一些后勤事项。您应该：

- 确定最佳时间和日期。

- 确定如何找到目标受众中的测试者。

- 确定理想的测试者数量。

- 创建测试会话的议程。

- 计划记录会话（如适用）。

- 选择会议的主持人和记录者（如果团队合作）。

&nbsp;

## 6. 准备主持会话

有效地进行用户测试可能具有挑战性——一旦您计划了会话，就需要为主持会话做好准备。您可以通过以下提示进行准备。

&nbsp;

### 观察而非指导

如果您亲自（或在线）进行测试，您可能会发现，在用户体验或审查您的设计时，坐在那里不说话是极其困难的。您可能还想插话并告诉他们如何做，如果他们遇到困难！这里需要找到平衡——如果您的测试者在某些基本内容上挣扎，以至于无法测试您的产品，请至少等 30 秒，记录下来，然后告诉他们该怎么做，以便您获得更多信息。另一方面，如果他们能够解决问题，他们的解决方案将是改善您设计的有价值信息。

&nbsp;

### 不要解释或辩解您的设计选择

如果您收集定性反馈——例如，通过与测试者对话——您可能会想解释事情或辩解当前项目的实施。这可能会让您感到好，因为这可能“修复”测试者的理解——但这并不会修复您正在测试的内容！

&nbsp;

### 不要在测试过程中解决问题

测试过程中出现的用户见解可能会立即使您进入问题解决模式，思考如何纠正提出的任何问题。您的测试者也可能开始专注于这一点，探索他们想到的潜在解决方案，而不是关注他们的体验。

&nbsp;

这些解决方案的建议并不是没有价值，但测试会话的目的是获取有关他们体验的见解，并深入了解他们的问题。准备好保持观察角色，积极倾听测试者告诉您的内容。您还可以准备温和地将测试者引导回他们正在解释的问题或下一个问题。如果您对此没有信心，可以尝试与其他创作者进行练习！

&nbsp;

## 7. 组织会话

测试会话的结构可能会有所不同，但主持人通常会使用以下大致结构：

- 如果作为小组进行测试，则进行介绍。

- 确定会议的目标。

- 解释录音政策（如适用），并确认测试者对此的同意。

- 提供测试材料，并观察测试者使用或审查它们。

- 提出您准备的问题。

- 为澄清目的提供参与者答案的摘要。

- 结束会话。

&nbsp;

### 主持的技巧和窍门

以下是一些有用的技巧和窍门，可以帮助您主持用户测试会话。

- 提醒自己，您并不是您的产品，每个产品在反馈中都会变得更好——但前提是您在关注用户告诉您的内容。

- 为参与者设定体验框架。当每位测试者进入时，与他们交谈并解释什么是用户测试。强调您希望得到所有反馈，负面反馈实际上可能比正面反馈更有帮助。请他们在使用产品或审查材料时尽可能多地交谈或“叙述”，这样您可以更深入地了解他们的思维过程。

- 当测试开始时，确保停止交谈并详细记录您的观察。瞬间看似清晰的事情如果仅依赖记忆很容易变得模糊。用户在哪些方面感到困惑？是否有功能他们未按预期使用？他们是否在做一些看似不合逻辑的事情？

- 如果用户长时间不说话，请轻声提醒他们重新启动内心独白，否则请假装您在单向镜后面。

- 如果您与一组测试者进行对话，请确保将他们都纳入讨论。温和地提示安静的测试者表达他们的想法，以确保他们的见解被包含在内。

&nbsp;

## 8. 会后

在测试会话结束后，您应：

- 确保会话已被录制（如适用）。

- 写下任何额外的笔记或观察。

- 与团队成员进行汇报（如适用）。

- 创建一份总结文档，突出需要解决的领域。

- 确定您将基于收集到的数据和反馈进行或不进行的更改。

&nbsp;

### 评估和采取反馈行动

当您收集完所有反馈后，是时候评估并思考如何回应了。仔细阅读您的笔记和问卷，并写下结果摘要，无

论是正面的还是负面的。这应是一个要点列表，例如：

- “用户没有注意到有不同种类的塔。”

- “用户觉得理解和使用上下文菜单很容易。”

&nbsp;

完成后，考虑您可以采取哪些行动来解决每个可能需要改进的问题，以及这些行动可能的依赖关系。这将帮助您评估响应识别问题的选项。

&nbsp;

您并不需要对每个用户测试结果采取行动，但倾听用户想告诉您的内容至关重要。如果您产品的一个重要部分运作不佳，值得削减一些功能，以专注于修复现有内容。

&nbsp;

## 9. 练习：迷你产品评估

在您完成本教程之前，花点时间扮演用户测试者的角色。您只需要一个开放的文档或一张纸条，以记录和组织您的想法。为此：

1. 选择一个或两个您认为特别出色的产品（数字或实体）。例如，一款用户体验特别良好的游戏或软件，或一件时尚而功能齐全的厨房用具。

&nbsp;

2. 尝试找出您为何如此喜欢该产品。使用以下问题进行帮助：
   
   - 它为您解决了哪些用户需求？
   
   - 对于您作为用户来说，体验中有哪些积极因素？
   
   - 使用时您的感受如何？
   
   - 当您开始使用它时，学习曲线有多陡峭？
   
   - 您会向其他人推荐它吗？进一步阐明您具体会推荐给谁，以及推荐的理由。

&nbsp;

3. 这是您非常喜欢的产品，但花点时间找出其需要改进的地方。使用以下问题进行帮助：
   
   - 您是否有相关的用户需求未能得到充分满足？
   
   - 您是否有渴望而非需求未能得到满足？
   
   - 在使用过程中，有哪些地方可以精细化体验？
   
   - 如果您可以对设计和制作该产品的人说一句话，那会是什么？

&nbsp;

4. 花一点时间评估您为该产品写下的反馈。如果您是设计和开发团队的一部分，这是否能给您提供足够的信息，以：
   
   - 清楚识别用户体验中的积极和消极方面？
   
   - 开始识别可能解决用户痛点的行动？

&nbsp;

如果没有，请尝试找出您会问的额外问题，以获取该信息——这将帮助您在为您正在处理的内容准备用户测试时界定问题！

&nbsp;

### 分享您的体验

您是否对自己对产品的评估深度感到惊讶？您是否需要确定很多后续问题来深化您的答案，就像某些测试者一样？花一点时间在教程评论中分享您对这个练习的简要反思，并探索他人的见解！

&nbsp;

## 10. 总结与下一步

在本教程中，您回顾了设置用户测试的过程，考虑了其挑战和提供的好处。

&nbsp;

真正倾听用户（测试者或其他用户）所告诉您的内容可能很困难，特别是当反馈是负面的。毕竟，您正在努力创造一种数字体验——如果这是您选择的个人项目，您可能对其有明确且令人信服的愿景。

&nbsp;

然而，为了创造最佳的实时体验，产品需要能够独立存在。如果测试者对您非常喜欢的游戏过场动画感到无聊，那么不论如何，这在玩家体验上都不起作用。如果测试者说您的应用程序控件太复杂，这并不是因为他们不欣赏您可能创建的复杂系统——而是因为它没有充分满足他们作为用户的需求。

&nbsp;

通过对反馈和您的体验进行批判性评估，然后实施更好地满足目标用户需求的变更，您可以提高体验的质量。

&nbsp;

为什么不尝试为下一个作品集项目计划和进行一次非正式的测试会话，与其他创作者一起？您可能会对获得的见解感到惊讶！

&nbsp;
